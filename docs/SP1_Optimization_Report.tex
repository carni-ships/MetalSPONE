\section{Executive Summary}

This report documents a systematic optimization effort applied to the SP1 v4.0.0 zero-knowledge STARK prover, targeting a memory-constrained 18GB Apple M3 Pro laptop. Over 21 sessions and 60+ individual optimizations, the Fibonacci benchmark proving time was reduced from \textbf{50.5 seconds to 0.8 seconds} --- a \textbf{63$\times$ speedup}.

The optimizations span six categories:

\begin{itemize}[nosep]
    \item \textbf{GPU acceleration} via Apple Metal (Poseidon2 Merkle hashing, NTT/DFT)
    \item \textbf{Algorithmic improvements} to FRI, PCS open, and permutation trace generation
    \item \textbf{Memory optimizations} (clone elimination, early drops, read-only references)
    \item \textbf{Shape tuning} for both core and recursion circuits (minimizing padding waste)
    \item \textbf{FRI parameter tuning} (FRI\_QUERIES, LOG\_BLOWUP)
    \item \textbf{Build-level optimizations} (fat LTO, jemalloc, native codegen)
\end{itemize}

At the 0.8s floor, costs are well-distributed across 10+ sub-phases with no single dominant bottleneck. Further gains would require architectural changes to the proof system itself.

The benchmark configuration is appropriate for development and performance testing. Production deployments would use higher FRI\_QUERIES at the cost of larger recursion circuits and proportionally slower compress phase.

\textbf{Important:} All core optimizations (GPU acceleration, shape tuning, batching, backtrace fix, LDE caching, clone elimination, batch inversion, etc.) apply equally to production-grade FRI configurations.

\section{Remaining Bottlenecks}

At 0.8s, costs are well-distributed across 10+ sub-phases with no single dominant bottleneck:

\begin{itemize}[nosep]
    \item \textbf{Byte chip} ($2^{16}$ = 65,536 rows): Inherent to SP1's lookup architecture (256$\times$256 table). Sets the minimum FRI height floor for all proofs.
    \item \textbf{ExtAlu=15} (32,768 rows): Inherent to proof verification arithmetic in the recursion circuit. Sets the recursion circuit floor.
    \item \textbf{pcs\_open} (158ms core + 88ms compress): Dominated by row reduction (compute-bound, not memory-bound) and FRI folding.
    \item \textbf{Quotient computation} (95ms core + 32ms compress): Constraint evaluation over the domain --- already uses precomputed interactions.
\end{itemize}

Further gains would require one or more of:

\begin{enumerate}[nosep]
    \item \textbf{Different proof system} --- alternative to FRI with lower per-proof overhead
    \item \textbf{Different recursion strategy} --- avoiding the recursive STARK-in-STARK approach
    \item \textbf{Custom silicon} --- dedicated hardware for BabyBear field arithmetic and Poseidon2
    \item \textbf{Smaller programs} --- reducing the Fibonacci benchmark itself (already near-minimal)
\end{enumerate}
